Purpose of This Working Document

This document is a technical working notebook for building the TA788 Quarto and Shinylive case study. It is deliberately more detailed than the final public-facing page because it records the evidence extraction, modelling logic, and R implementation plan step by step.

Phase 1: EAG Audit Log

The first task is not to write R code. The first task is to identify which assumptions matter to the appraisal decision and which assumptions the EAG challenged. In an oncology partitioned survival model, the most decision-sensitive nodes usually sit in survival extrapolation, treatment effect duration, utilities, and drug costs.

The table below records the initial audit findings extracted from the public NICE TA788 appraisal evidence.

Audit domain Extracted fact Source evidence Why this matters for EAG review
OS extrapolation The company originally preferred a generalised gamma model for both avelumab and watchful waiting / best supportive care. The ERG preferred a log-normal model. NICE committee papers report that the company selected generalised gamma because 10-year survival predictions aligned with clinical estimates. The ERG stated that log-normal had better fit and more plausible long-term watchful waiting estimates. Overall survival extrapolation is usually the dominant source of lifetime QALY uncertainty. A more optimistic OS tail can materially reduce the ICER by creating additional survival benefit far beyond observed trial follow-up.
PFS extrapolation The company used BICR-assessed PFS with a 3-knot normal spline-based model for both arms. The ERG preferred investigator-assessed PFS, using a 3-knot hazard spline for avelumab and a 3-knot odds spline for watchful waiting. The ERG preferred investigator-assessed PFS because it more closely reflected UK clinical decision-making, including the timing of post-progression therapy initiation. This is both a statistical and clinical-practice issue. BICR may be cleaner for trial measurement, but investigator assessment may better represent real-world NHS treatment decisions.
Treatment stopping and treatment effect cap Avelumab is recommended only if treatment stops after 5 years of uninterrupted treatment, or earlier if disease progresses. The treatment effect cap is applied 1 year after stopping, so the cap begins at year 6. NICE final guidance states that a treatment effect cap 1 year after stopping avelumab should be included in the model. Immunotherapy models can overstate value if they assume indefinite benefit after treatment discontinuation. NICE committees often require explicit treatment effect duration assumptions when long-term evidence is uncertain.
Implementation of the cap Beyond the cap time point, the hazard of death for avelumab is set equal to the watchful waiting arm. In modelling terms, the OS hazard ratio becomes 1 after the cap. The company and ERG agreed after technical engagement that the appropriate implementation was to set avelumab hazards equal to watchful waiting beyond the cap time point. The model should cap the incremental hazard benefit, not impose an abrupt fall in survival probability. This avoids a biologically impossible discontinuity in the survival curve.
Health-state utilities Base-case utility values came from JAVELIN Bladder 100 EQ-5D data, with EQ-5D-5L responses crosswalked to EQ-5D-3L. Progression-free utility was 0.772 and post-progression utility was 0.698. Company evidence reported utility values by progression status: progression-free 0.772 and post-progression 0.698. In a partitioned survival model, health-state utilities convert state occupancy into QALYs. A higher progression-free utility increases the value of delaying progression.
Alternative utility scenario Scenario values from NICE TA519 were also considered: progression-free 0.731 and progressed disease 0.641. The company evidence submission reported TA519-derived scenario utilities for progression-free and progressed patients. Scenario utilities can test whether the ICER is robust to different health-related quality-of-life sources.
Adverse-event disutility Grade 3 or higher adverse-event disutilities were included separately, using utility decrements from published literature and adverse-event rates from JAVELIN Bladder 100. The ERG report noted that adverse events of grade 3 or higher were included separately in the model. AE disutility is likely small relative to OS/PFS extrapolation, but its transparent inclusion is part of a complete economic model.
Avelumab acquisition cost Public list price was GBP 768 per 200 mg vial. The model used a flat dose of 800 mg every 2 weeks, requiring four vials and giving GBP 3,072 per dose before confidential discount. Company evidence reported avelumab as a 200 mg vial, administered as an 800 mg IV infusion every 2 weeks, with a list price of GBP 768 per vial. Drug acquisition cost is a major driver of incremental cost. The public portfolio model should clearly distinguish public list price from the confidential discounted NHS price.
Commercial arrangement Avelumab had a patient access scheme or commercial arrangement, but the discount size was commercial in confidence. NICE final guidance states that the company has a commercial arrangement and that the discount size is confidential. The public model must not invent the confidential net price. It can use public list price and allow scenario discounts for learning purposes.
Administration cost Avelumab administration cost was GBP 183.54 per administration, based on outpatient simple parenteral chemotherapy, NHS Reference Cost SB12Z. Company evidence used GBP 183.54 for a single administration because avelumab is administered once every 14-day cycle over 60 minutes. Administration costs recur every 2 weeks while patients remain on treatment, so they accumulate materially over the treatment period.

Modelling Translation

The audit log must now be translated into model inputs. This section explains how each evidence item becomes an R modelling object.

0.1 Survival Curves

The partitioned survival model needs two survival functions for each arm:

\[S_{\mathrm{PFS}}(t)\]

\[S_{\mathrm{OS}}(t)\]

These curves determine health-state occupancy directly:

\[\pi_{\mathrm{PF}}(t) = S_{\mathrm{PFS}}(t)\]

\[\pi_{\mathrm{PD}}(t) = S_{\mathrm{OS}}(t) - S_{\mathrm{PFS}}(t)\]

\[\pi_{\mathrm{Death}}(t) = 1 - S_{\mathrm{OS}}(t)\]

The essential structural rule is:

\[S_{\mathrm{OS}}(t) \geq S_{\mathrm{PFS}}(t)\]

If this condition is violated, the model has produced a structural failure because a patient cannot be progression-free after death. The future Shiny module should therefore include an automatic warning if PFS exceeds OS at any cycle.

0.2 Treatment Effect Cap

The treatment effect cap is the most important TA788-specific modelling issue for this portfolio case.

The appraisal logic is:

  • Avelumab treatment stops at 5 years of uninterrupted treatment.
  • The treatment effect cap is applied 1 year after stopping.
  • Therefore, the cap is applied at year 6.
  • After the cap, the avelumab OS hazard is set equal to the watchful waiting OS hazard.
  • In hazard-ratio terms, the post-cap OS hazard ratio is 1.

This should be coded as a hazard-level operation rather than a survival-level discontinuity. In other words, the model should not suddenly reduce the avelumab survival curve at year 6. Instead, it should propagate survival forward using the watchful waiting hazard after the cap time.

0.3 Utilities

The base-case health-state utility inputs are:

Health state Utility
Progression-free 0.772
Progressed disease 0.698

The initial QALY calculation should use:

\[QALY = \sum_t \left[\pi_{\mathrm{PF}}(t)u_{\mathrm{PF}} + \pi_{\mathrm{PD}}(t)u_{\mathrm{PD}}\right]\Delta t \times d(t)\]

where:

  • \(\Delta t\) is the cycle length in years.
  • \(d(t)\) is the discount factor.
  • \(u_{\mathrm{PF}}\) is progression-free utility.
  • \(u_{\mathrm{PD}}\) is progressed disease utility.

The immediate coding objective is therefore limited to the survival and occupancy engine:

  1. create a monthly time grid;
  2. generate synthetic PFS and OS survival curves;
  3. convert those curves into partitioned survival state occupancy;
  4. verify that each cycle sums to 1;
  5. flag any cycle where PFS exceeds OS.

This scope is deliberately narrow. In an EAG-style audit, a simple engine with explicit assumptions is more credible than a complex interactive model whose parameters are not traceable.

Phase 2 Build Plan

The next step is to build clean R functions that are separate from Shiny reactivity.

The first function should generate survival probabilities over a 30-year monthly horizon. The second function should convert PFS and OS survival probabilities into health-state occupancy. The third function should calculate discounted QALYs and costs.

The functions should be written in this order:

  1. make_time_grid()
  2. weibull_survival()
  3. calculate_state_occupancy()
  4. check_pfs_os_consistency()

Only after these functions work independently should they be embedded inside a Shinylive app.

R Learning Notes

For a new R modeller, the key design principle is to separate mathematical logic from interface logic.

The mathematical engine should not know anything about Shiny inputs such as input$waning_start or input$os_distribution. It should only accept ordinary R arguments and return ordinary R objects. This makes the model testable in the R console before any user interface is built.

Phase 2.1: Minimal PSM Engine

This section builds the smallest useful partitioned survival model engine. The survival parameters below are synthetic and are used only to test the calculation structure. They are not TA788-validated parameters and should not be interpreted as evidence-based JAVELIN Bladder 100 estimates.

The immediate goal is to confirm that the mathematical engine can:

  1. create a monthly model time grid;
  2. generate plausible synthetic PFS and OS survival curves;
  3. translate PFS and OS into progression-free, progressed disease, and death state occupancy;
  4. verify that each cycle sums to 1;
  5. flag any structural failure where PFS exceeds OS.
Code 
check_positive_number <- function(x, name) {
  if (!is.numeric(x) || length(x) != 1 || is.na(x) || !is.finite(x) || x <= 0) {
    stop(paste0("`", name, "` must be a single positive finite number."))
  }
}

make_time_grid <- function(horizon_years = 30, cycle_length_months = 1) {
  check_positive_number(horizon_years, "horizon_years")
  check_positive_number(cycle_length_months, "cycle_length_months")

  horizon_months <- horizon_years * 12

  tibble(
    cycle = seq(0, horizon_months, by = cycle_length_months),
    time_months = cycle
  )
}

weibull_survival <- function(time_months, shape, scale) {
  check_positive_number(shape, "shape")
  check_positive_number(scale, "scale")

  # lower.tail = FALSE returns S(t) = P(T > t), not the cumulative event probability.
  pweibull(
    q = time_months,
    shape = shape,
    scale = scale,
    lower.tail = FALSE
  )
}

check_same_length <- function(x, expected_length, name) {
  if (length(x) != expected_length) {
    stop(paste0("`", name, "` must have length ", expected_length, "."))
  }
}

check_btwn01 <- function(x, name) {
  if (any(x < 0 | x > 1)) {
    stop(paste0("`", name, "` values must be between 0 and 1."))
  }
}

calculate_state_occupancy <- function(time_grid, pfs_survival, os_survival) {
  if (!all(c("cycle", "time_months") %in% names(time_grid))) {
    stop("time_grid must contain cycle and time_months columns.")
  }
  check_same_length(pfs_survival, nrow(time_grid), "pfs_survival")
  check_same_length(os_survival, nrow(time_grid), "os_survival")

  check_btwn01(pfs_survival, "pfs_survival")
  check_btwn01(os_survival, "os_survival")

  time_grid |>
    mutate(
      pfs_survival = pfs_survival,
      os_survival = os_survival,
      progression_free = pfs_survival,
      progressed_disease = os_survival - pfs_survival,
      death = 1 - os_survival,
      state_sum = progression_free + progressed_disease + death,
      pfs_exceeds_os = pfs_survival > os_survival
    )
}

The first function creates the monthly model calendar. The second function provides a simple Weibull survival generator using base R’s standard Weibull parameterisation. In pweibull(), lower.tail = FALSE returns the survival probability directly: \(S(t) = P(T > t)\). The third function applies the partitioned survival identities directly and stores two audit columns: state_sum and pfs_exceeds_os.

Phase 2.2: QALY Accumulation

This section adds the first health economic outcome to the minimal PSM engine: quality-adjusted life years. The calculation uses the public TA788 health-state utility values extracted in Phase 1:

Health state Utility
Progression-free 0.772
Progressed disease 0.698

The calculation below still uses synthetic survival curves from Phase 2.1. Therefore, the resulting QALY total is a test of the calculation engine only, not a TA788 cost-effectiveness result.

Code 
add_monthly_discount_weights <- function(model_trace, annual_discount_rate) {
  if (!"time_months" %in% names(model_trace)) {
    stop("model_trace must contain a time_months column.")
  }

  check_btwn01(annual_discount_rate, "annual_discount_rate")

  monthly_discount_rate <- (1 + annual_discount_rate)^(1 / 12) - 1

  model_trace |>
    mutate(
      monthly_discount_rate = monthly_discount_rate,
      discount_weight = 1 / ((1 + monthly_discount_rate)^time_months)
    )
}

calculate_qalys <- function(
  state_occupancy,
  utility_pf = 0.772,
  utility_pd = 0.698,
  annual_discount_rate = 0.035,
  cycle_length_months
) {
  required_columns <- c(
    "cycle",
    "time_months",
    "progression_free",
    "progressed_disease"
  )

  if (!all(required_columns %in% names(state_occupancy))) {
    stop("state_occupancy must contain cycle, time_months, progression_free, and progressed_disease columns.")
  }

  check_btwn01(utility_pf, "utility_pf")
  check_btwn01(utility_pd, "utility_pd")
  check_positive_number(cycle_length_months, "cycle_length_months")

  state_occupancy |>
    add_monthly_discount_weights(
      annual_discount_rate = annual_discount_rate
    ) |>
    mutate(
      cycle_length_months = cycle_length_months,
      undiscounted_utility_months_cycle = (
        progression_free * utility_pf +
          progressed_disease * utility_pd
      ) * cycle_length_months,
      discounted_utility_months_cycle =
        undiscounted_utility_months_cycle * discount_weight
    )
}

There are two modelling choices to notice here.

  • First, the model keeps the main time scale in months from survival generation through state occupancy and QALY accumulation.
  • Second, the cycle-level calculation first accumulates utility-months, which is easier to read in a monthly model.
  • Third, utility-months are converted into QALYs only in the summary step by dividing the total by 12.
  • Fourth, the annual discount rate is converted into a monthly discount rate through a shared helper function, and discounting is then applied month by month. Half-cycle correction is intentionally deferred to a later section.

Phase 2.3: Two-arm QALY Comparison

This section converts the single-arm engine into a minimal two-arm comparison. The parameters below are synthetic. They are designed only to test whether the model can compare an intervention arm with a comparator arm and calculate incremental QALYs.

The two-arm structure is the point at which the model starts to resemble a cost-effectiveness analysis. Costs are still excluded at this stage, so this section calculates incremental QALYs only.

Code 
run_single_arm_qaly_model <- function(
  arm_name,
  pfs_shape,
  pfs_scale,
  os_shape,
  os_scale,
  time_grid,
  utility_pf,
  utility_pd,
  annual_discount_rate,
  cycle_length_months
) {
  pfs_survival <- weibull_survival(
    time_months = time_grid$time_months,
    shape = pfs_shape,
    scale = pfs_scale
  )

  os_survival <- weibull_survival(
    time_months = time_grid$time_months,
    shape = os_shape,
    scale = os_scale
  )

  state_occupancy <- calculate_state_occupancy(
    time_grid = time_grid,
    pfs_survival = pfs_survival,
    os_survival = os_survival
  )

  qaly_trace <- calculate_qalys(
    state_occupancy = state_occupancy,
    utility_pf = utility_pf,
    utility_pd = utility_pd,
    annual_discount_rate = annual_discount_rate,
    cycle_length_months = cycle_length_months
  )

  qaly_trace |>
    mutate(arm = arm_name)
}

The wrapper function above is deliberately simple. It does not introduce new mathematics. It only sequences the existing functions: generate PFS, generate OS, calculate state occupancy, and accumulate QALYs.

The 5-year stopping rule, time-on-treatment evidence, treatment discontinuation, monitoring costs, adverse-event costs, and post-progression costs are not yet included.

Code 
calculate_public_costs <- function(
  model_trace,
  arm_name,
  cycle_length_months,
  drug_cost_per_dose = 3072,
  administration_cost_per_dose = 183.54,
  dosing_interval_days = 14,
  annual_discount_rate = 0.035,
  treatment_stop_months = Inf
) {
  required_columns <- c(
    "arm",
    "time_months",
    "progression_free"
  )

  if (!all(required_columns %in% names(model_trace))) {
    stop("model_trace must contain arm, time_months, and progression_free columns.")
  }

  check_positive_number(cycle_length_months, "cycle_length_months")
  check_positive_number(drug_cost_per_dose, "drug_cost_per_dose")
  check_positive_number(administration_cost_per_dose, "administration_cost_per_dose")
  check_positive_number(dosing_interval_days, "dosing_interval_days")
  if (!is.infinite(treatment_stop_months)) {
    check_positive_number(treatment_stop_months, "treatment_stop_months")
  }

  days_per_month <- 365.25 / 12
  doses_per_month <- days_per_month / dosing_interval_days

  model_trace |>
    add_monthly_discount_weights(
      annual_discount_rate = annual_discount_rate
    ) |>
    mutate(
      doses_per_cycle = doses_per_month * cycle_length_months,
      treatment_allowed = arm == arm_name & time_months <= treatment_stop_months,
      treated_proportion = if_else(treatment_allowed, progression_free, 0),
      drug_cost_cycle = if_else(
        arm == arm_name,
        treated_proportion * doses_per_cycle * drug_cost_per_dose,
        0
      ),
      administration_cost_cycle = if_else(
        arm == arm_name,
        treated_proportion * doses_per_cycle * administration_cost_per_dose,
        0
      ),
      total_public_cost_cycle = drug_cost_cycle + administration_cost_cycle,
      discounted_public_cost_cycle = total_public_cost_cycle * discount_weight
    )
}

This function uses the same month-by-month discounting logic as the QALY function. The dosing frequency is converted into an approximate monthly number of doses using 365.25 / 12 / 14, which gives the average number of 14-day administrations per month.

Phase 2.6: OS Treatment Effect Cap

This section implements the TA788 treatment effect cap at the hazard level. The cost stopping rule ends avelumab treatment at 5 years. The treatment effect cap is applied 1 year later, at 6 years, by setting the avelumab OS hazard equal to the watchful waiting OS hazard.

The key modelling distinction is that the treatment effect is capped abruptly at the hazard level, but the avelumab survival curve remains continuous. The model should not impose a sudden drop in survival probability at the cap time.

Code 
survival_to_monthly_hazard <- function(survival_probabilities) {
  if (!is.numeric(survival_probabilities) || any(is.na(survival_probabilities))) {
    stop("survival_probabilities must be a numeric vector without missing values.")
  }

  if (any(survival_probabilities < 0 | survival_probabilities > 1)) {
    stop("survival_probabilities must contain values between 0 and 1.")
  }

  survival_lag <- lag(survival_probabilities)

  monthly_hazard <- -log(survival_probabilities / survival_lag)
  monthly_hazard[1] <- 0
  monthly_hazard
}

reconstruct_survival_from_hazard <- function(monthly_hazard) {
  if (!is.numeric(monthly_hazard) || any(is.na(monthly_hazard))) {
    stop("monthly_hazard must be a numeric vector without missing values.")
  }

  if (any(monthly_hazard < 0)) {
    stop("monthly_hazard cannot contain negative values.")
  }

  exp(-cumsum(monthly_hazard))
}

The first helper converts survival probabilities into monthly discrete hazards. The second helper reconstructs a continuous survival curve from monthly hazards. Together, they let the model modify hazards after the cap time without directly forcing a discontinuous survival drop.

Phase 2.7: Half-Cycle Correction for QALYs

This section adds a basic half-cycle correction for QALYs. In a cycle-based model, patients do not usually transition exactly at the beginning or end of a cycle. The half-cycle correction approximates this by giving half weight to the first and last cycles, while giving full weight to all cycles in between.

This section applies half-cycle correction to QALYs only. Drug acquisition and administration costs are not adjusted here because those costs are event-like treatment costs linked to dosing. Cost half-cycle correction can be considered later if the model adds broader monthly disease management costs.

Code 
add_half_cycle_weights <- function(model_trace) {
  required_columns <- c("arm", "cycle")

  if (!all(required_columns %in% names(model_trace))) {
    stop("model_trace must contain arm and cycle columns.")
  }

  model_trace |>
    group_by(arm) |>
    arrange(cycle, .by_group = TRUE) |>
    mutate(
      half_cycle_weight = if_else(
        row_number() == 1 | row_number() == n(),
        0.5,
        1
      )
    ) |>
    ungroup()
}

The function above creates a simple weight column. For each arm, the first and final cycles receive a weight of 0.5. All other cycles receive a weight of 1.
