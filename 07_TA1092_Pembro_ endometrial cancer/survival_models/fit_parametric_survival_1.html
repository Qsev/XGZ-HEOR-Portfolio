Learning Note: Parametric Survival Fitting for TA1092

Step-by-step R workflow using reconstructed pseudo-IPD

Purpose

This note turns the batch script fit_parametric_survival.R into a step-by-step learning document.

The goal is not just to run code. The goal is to understand:

  • what the pseudo-IPD contains;
  • how Surv() represents survival data;
  • what flexsurvreg() estimates;
  • how AIC/BIC are used for first-pass model comparison;
  • why AIC-selected survival curves still need clinical and EAG-style critique.

9. Define a Safe Fitting Function

Some distributions can fail for sparse or immature OS data. This function catches failures and returns a row explaining what happened.

Show R code 
`%||%` <- function(x, y) if (is.null(x)) y else x

fit_one_distribution <- function(dat, dist_label, dist_name) {
  tryCatch(
    {
      fit <- flexsurvreg(Surv(time_months, status) ~ 1, data = dat, dist = dist_name)
      n_par <- nrow(fit$res)
      fit_aic <- as.numeric(fit$AIC %||% NA_real_)
      fit_loglik <- as.numeric(fit$loglik %||% NA_real_)

      tibble(
        dist_label = dist_label,
        dist_name = dist_name,
        fit = list(fit),
        converged = TRUE,
        error = NA_character_,
        aic = fit_aic,
        bic = -2 * fit_loglik + log(nrow(dat)) * n_par,
        loglik = fit_loglik,
        n = nrow(dat),
        events = sum(dat$status)
      )
    },
    error = function(e) {
      tibble(
        dist_label = dist_label,
        dist_name = dist_name,
        fit = list(NULL),
        converged = FALSE,
        error = conditionMessage(e),
        aic = NA_real_,
        bic = NA_real_,
        loglik = NA_real_,
        n = nrow(dat),
        events = sum(dat$status)
      )
    }
  )
}

What this function is doing

This function is a small wrapper around flexsurvreg(). The reason to write a wrapper is that we want to fit many distributions across many curves. Some fits may fail, especially for immature OS curves with few events. If one fit fails, we do not want the whole document to stop.

The function has three inputs:

fit_one_distribution(dat, dist_label, dist_name)
  • dat: the pseudo-IPD for one curve, for example pmmr_pfs_pembro_ipd.
  • dist_label: the readable name used in output tables, for example "weibull".
  • dist_name: the name required by flexsurvreg(), for example "weibull" or "llogis".

The helper:

`%||%` <- function(x, y) if (is.null(x)) y else x

means: if x is missing or NULL, use y instead. Here it prevents the code from breaking if a fitted object does not contain AIC or loglik.

The core model fit is:

fit <- flexsurvreg(Surv(time_months, status) ~ 1, data = dat, dist = dist_name)

This means:

  • use time_months and status from dat;
  • fit one survival curve, because the right-hand side is ~ 1;
  • use the parametric distribution named in dist_name.

The object fit is a fitted survival model. It contains parameter estimates, log-likelihood, AIC, and other information. We store it inside a tibble using:

fit = list(fit)

This creates a list-column. Without list(), a complex model object cannot fit cleanly inside one table cell.

The successful-output part returns one row:

tibble(
  dist_label = dist_label,
  dist_name = dist_name,
  fit = list(fit),
  converged = TRUE,
  error = NA_character_,
  aic = fit_aic,
  bic = -2 * fit_loglik + log(nrow(dat)) * n_par,
  loglik = fit_loglik,
  n = nrow(dat),
  events = sum(dat$status)
)

Key fields:

  • converged = TRUE: the model fitted successfully.
  • error = NA_character_: there was no error message.
  • aic: model fit criterion reported by flexsurv.
  • bic: calculated manually using -2 * logLik + log(n) * number_of_parameters.
  • n: number of pseudo-patients in this curve.
  • events: number of observed events.

The tryCatch() part is the safety mechanism:

tryCatch(
  { successful fitting code },
  error = function(e) { failure output }
)

If flexsurvreg() fails, the function still returns a row. That row has:

  • fit = list(NULL)
  • converged = FALSE
  • error = conditionMessage(e)
  • aic, bic, loglik as NA

This is useful for modelling workflow QA. Instead of silently losing failed fits, the output table records exactly which distribution failed and why.

In HEOR work, this matters because sparse OS data can make complex models unstable. A reviewer or EAG would want to know not only which model had the best AIC, but also whether some candidate models failed, behaved oddly, or were unsuitable for extrapolation.

predict_survival <- function(fit, times) {
  s <- summary(fit, t = times, type = "survival")

  if (is.data.frame(s)) {
    return(as.numeric(s$est))
  }

  if (is.list(s) && length(s) == 1 && is.data.frame(s[[1]])) {
    return(as.numeric(s[[1]]$est))

  map_dbl(s, ~.x$est)
}

The point of the plot is more modest: it lets us check whether the fitted curve tracks the reconstructed KM reasonably before we start interpreting the long-term extrapolation.

The broader EAG-style warning is that a curve can have the best AIC and still become implausible later. Examples would include:

  • a PFS curve that remains high for decades despite advanced cancer;

18. Issue 3 Demonstration: Short Follow-up and Extrapolation Risk

The EAG’s Issue 3 is not just saying that longer follow-up would be preferable. The practical concern is that KEYNOTE-868 provides relatively early survival evidence, while the economic model requires long-term PFS and OS predictions.

In the EAG report, several values are redacted in the Issue 3 table. Later consultation comments in the same committee papers refer to the median follow-up as 16.3 months. I use that value below as a working interpretation, while noting that the value is redacted in the Issue 3 table itself.

This section uses pMMR OS, pembro arm as the worked example. OS is usually one of the most important drivers of life years and QALYs in oncology models, and short follow-up is especially important when OS benefit is immature.

The important point is that the EAG did not apply a simple universal rule such as “follow-up below X months is unacceptable”. The concern comes from the combination of short follow-up, immature OS, and a model that needs to estimate survival far beyond the observed trial period.

Two judgement points are especially important here.

First, median survival is a maturity signal. If median OS has not been reached in the intervention arm, then fewer than half of patients in that arm have died by the data cut. That is clinically encouraging, but it also means the long-term OS curve is not well observed. The model must infer the later part of OS from limited event data.

Second, median follow-up should be interpreted against treatment duration. Pembrolizumab treatment in this regimen can last for around 2.2 years, but the median follow-up referred to in the committee papers is around 16.3 months. This means the median patient had not yet been followed for as long as the maximum planned active treatment period. From an EAG perspective, that creates uncertainty not only about survival during treatment, but also about what happens after treatment stops.

18.6 Appraisal Interpretation

This section turns the EAG’s Issue 3 into a reproducible modelling demonstration:

  • the EAG’s concern is translated into concrete modelling checks;
  • the observed follow-up, 2-year boundary, and 20-year horizon are shown on the same scale;
  • alternative distributions show the range of plausible long-term tails;
  • landmark predictions quantify how much the tails differ;
  • the interpretation links directly to NICE/EAG judgement about survival extrapolation uncertainty.

The key portfolio message is: short follow-up matters when the cost-effectiveness result depends on survival benefits generated beyond the observed trial period. The issue is not that extrapolation is avoidable; oncology economic models often require extrapolation. The EAG concern is that, with immature OS and limited follow-up, the long-term survival benefit may be driven more by modelling assumptions than by observed trial evidence.

19.2 pMMR Subgroup: AIC-Selected Standard Parametric Models

The pMMR analysis uses the AIC-best standard parametric distribution for each of the four curves (CT PFS, CT OS, pembro PFS, pembro OS), selected from the fitting grid in Section 14. Survival curves, state occupancy, costs, and QALYs are computed over a 35-year horizon.

19.2.1 Survival Curves to Health-State Occupancy

In a three-state PSM:

  • progression-free = PFS;
  • progressed disease = OS - PFS;
  • dead = 1 - OS.

This is why survival extrapolation matters for cost-effectiveness. If OS is optimistic, patients remain alive longer and generate more life years and QALYs.

There is one structural rule in a PSM: PFS should not exceed OS. PFS is the proportion alive and progression-free. OS is the proportion alive. Since every progression-free patient must also be alive, PFS should always be less than or equal to OS.

The source materials indicate that the company model included a limit to ensure that PFS could not exceed OS, applied at the per-cycle hazard level. This matters because independently fitted PFS and OS curves can otherwise cross in long-term extrapolation. I cannot reproduce the exact hazard-level implementation without the company workbook, so this public-data teaching model uses a transparent probability-level approximation:

PFS_constrained = min(PFS, OS)

This keeps the simplified PSM structurally coherent. It is not intended to replace full curve-pair selection in a formal submission.

19.2.4 OS Tail Sensitivity

Issue 5 is about the uncertain degree of OS benefit. A simple way to demonstrate this is to reduce the long-term OS separation between arms after the EAG’s 2-year boundary.

This scenario is not an EAG preferred model. It is a teaching sensitivity: after 104 weeks, the pembro OS benefit is gradually reduced so that only 50% of the modelled OS separation remains by 10 years.

apply_os_tail_reduction <- function(dat, start_week = 104, end_week = 520, final_fraction = 0.5) {
  dat |>
    select(arm, time_weeks, time_months, PFS, OS) |>
    tidyr::pivot_wider(names_from = arm, values_from = c(PFS, OS)) |>
    mutate(
      reduction_fraction = case_when(
        time_weeks <= start_week ~ 1,
        time_weeks >= end_week ~ final_fraction,
        TRUE ~ 1 - (1 - final_fraction) * (time_weeks - start_week) / (end_week - start_week)
      ),
      `OS_Pembro + chemo` = `OS_Placebo + chemo` +
        (`OS_Pembro + chemo` - `OS_Placebo + chemo`) * reduction_fraction
    ) |>
    select(time_weeks, time_months, starts_with("PFS_"), starts_with("OS_")) |>
    pivot_longer(
      cols = -c(time_weeks, time_months),
      names_to = c("endpoint", "arm"),
      names_sep = "_",
      values_to = "survival"
    ) |>
    pivot_wider(names_from = endpoint, values_from = survival) |>
    mutate(
      PF = pmin(PFS, OS),
      PD = pmax(OS - PFS, 0),
      Dead = pmax(1 - OS, 0)
    )
}

This is the bridge to Issue 5. If reducing the long-term OS separation reduces incremental QALYs and increases the ICER, then the OS tail is decision-relevant. That is why the EAG focuses on whether the company’s long-term OS benefit is clinically plausible.

19.3 dMMR Subgroup: EAG-Preferred Models (Table 2)

This section computes the dMMR ICER using the EAG’s preferred distributions from Table 2 of the EAG supplementary report.

Two structural caveats apply before interpreting the output:

  • The EAG’s pMMR preferred models are spline-based (1-knot hazards, 2-knot hazards, 1-knot normal), which are outside the current candidate distribution set. The dMMR preferred models are all standard parametric distributions and can be extracted directly from fit_tbl.
  • Utility values (PF = 0.814, PD = 0.720) were collected from the pMMR cohort only. KEYNOTE-868 did not collect dMMR HRQoL data due to insufficient power in the smaller dMMR cohort. Applying pMMR utilities to dMMR patients is an approximation with additional uncertainty.

Show R code 
ce_trace_dmmr <- psm_dmmr |>
  group_by(arm) |>
  arrange(time_weeks, .by_group = TRUE) |>
  mutate(
    discount        = discount_factor(time_weeks, ce_params$annual_discount_rate),
    death_increment = pmax(Dead - lag(Dead, default = 0), 0),
    pf_resource_cost = case_when(
      time_weeks <= ce_params$comparator_treatment_cap_weeks ~
        ce_params$weekly_cost_pf_initial,
      arm == "Pembro + chemo" & time_weeks <= ce_params$pembro_treatment_cap_weeks ~
        ce_params$weekly_cost_pf_pembro_maint,
      time_weeks <= 104 ~
        ce_params$weekly_cost_pf_offtreatment,
      TRUE ~
        ce_params$weekly_cost_pf_offtreatment_yr3
    ),
    qaly = (PF * ce_params$utility_pf + PD * ce_params$utility_pd) *
      ce_params$cycle_length_years * discount,
    disease_management_cost = (
      PF * pf_resource_cost + PD * ce_params$weekly_cost_pd
    ) * discount,
    treatment_cost = case_when(
      arm == "Pembro + chemo" & time_weeks <= ce_params$pembro_combination_weeks ~
        PF * ce_params$weekly_cost_pembro_combination *
          (1 - ce_params$pembro_discount) * discount,
      arm == "Pembro + chemo" & time_weeks <= ce_params$pembro_treatment_cap_weeks ~
        PF * ce_params$weekly_cost_pembro_maintenance *
          (1 - ce_params$pembro_discount) * discount,
      arm == "Placebo + chemo" & time_weeks <= ce_params$comparator_treatment_cap_weeks ~
        PF * ce_params$weekly_cost_comparator_chemo * discount,
      TRUE ~ 0
    ),
    ae_cost = case_when(
      arm == "Pembro + chemo"  & time_weeks == 0 ~ ce_params$one_off_ae_cost_pembro,
      arm == "Placebo + chemo" & time_weeks == 0 ~ ce_params$one_off_ae_cost_comparator,
      TRUE ~ 0
    ),
    terminal_care_cost = death_increment * ce_params$terminal_care_cost * discount,
    total_cost = disease_management_cost + treatment_cost + ae_cost + terminal_care_cost
  ) |>
  ungroup()

ce_results_dmmr <- ce_trace_dmmr |>
